# Kadr: гайд бета-тестера (10 минут)

## Перед началом

1. Сделайте бэкап архива. Даже при copy-by-default бэкап — условие участия.
2. Начните с тестовой папки 100–1000 файлов, не со всего архива.
3. Проверьте свободное место: раскладка `copy` создаёт копии.

## Первый результат

```bash
kadr init
kadr scan /path/to/test-folder
kadr analyze
kadr plan --preset date --root /path/to/sorted --tree
```

Посмотрите дерево «что куда». Если всё устраивает:

```bash
kadr apply <plan_id>
```

Откат:

```bash
kadr undo <plan_id>
```

`kadr doctor` покажет профиль, индекс, лицензии и известные ограничения.

## Что проверить

- Даты: где нет EXIF, дата может быть из имени/mtime — смотрите бейдж
  `date_confidence` и review.
- Группы: RAW+JPEG+XMP и Live Photo должны переезжать вместе.
- Дубли: точные дубли не удаляются; почти-дубли — только review (P1).
- Поиск: `kind:photo camera:Canon`, затем фраза по-русски. Если семантика
  недоступна, CLI/UI покажет `degraded` и причину — это ожидаемо на Lite.
- VLM: на CPU не включайте «улучшить описания» в основном потоке. Ночная задача —
  только явно, от сети, с ETA; она experimental.

## Как сообщить о проблеме

Приложите: ОС/версию, профиль, вывод `kadr doctor`, команду, ожидаемое/фактическое
поведение. Не прикладывайте чужие персональные данные и сами медиа без согласия.
Критические проблемы (потеря/порча оригинала, path traversal, утечка PII) —
по `SECURITY.md`, не публичным issue.

## Известные ограничения

Прочитайте [`KNOWN_LIMITATIONS.md`](KNOWN_LIMITATIONS.md) до теста: там честно
перечислено, что v0.1 не умеет (VLM на CPU, ANN, лица, embedded MP4/MOV/MP3,
свойства ОС).
