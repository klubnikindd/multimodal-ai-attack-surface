## 1. Продуктовые границы

### 1.1 Обещание продукта (то, что пишем на лендинге)

> «Разберёт архив из 200 000 фото и видео по папкам, которые вы задали, найдёт дубли, подпишет содержимое и сделает библиотеку поисковой. Работает оффлайн. Ничего не удаляет и не портит: любую раскладку можно откатить одной кнопкой.»

Три вещи, которые продают продукт фотографу, в порядке важности:
1. **Предсказуемость и безопасность** (undo, dry-run, оригиналы целы).
2. **Скорость разбора** (10k файлов за минуты, а не за ночь).
3. **Умные теги и поиск** (то, чего нет у PhotoMove Pro).

### 1.2 Персоны и их сценарии

| Персона | Архив | Главный сценарий | Что для него «магия» |
|---|---|---|---|
| Свадебный/репортажный фотограф | 100–500k, RAW+JPEG, карты памяти | Ingest с карты → раскладка по съёмкам → отбор | Авто-группировка по съёмкам (дата+время+камера+гео), отбор лучших из серии, поиск «невеста с букетом» |
| Видеограф | 1–20 ТБ, MP4/MOV/BRAW, длинные клипы | Разложить по проектам, найти нужный дубль | Поиск по произнесённой фразе с тайм-кодом, авто-обложка клипа, «дрон / интервью / B-roll» |
| Энтузиаст / семейный архив | 20–80k, телефон + скриншоты + мемы | «Сделай порядок» | Даты/события, лица (opt-in), «убери скриншоты и мемы из фото», дубли из мессенджеров |

### 1.3 Скоуп v0.1 (что режем)

**P0 — обязательно в v0.1:** сканер+индекс (SQLite), правила сортировки с dry-run/undo, точные дубли, дата/камера/гео из метаданных, CLIP/SigLIP-эмбеддинги + семантический поиск и zero-shot теги, OCR, XMP-sidecar запись, галерея+фильтры+ручная правка тегов, установщики под 3 ОС, защитный контур (§THREAT_MODEL P0).

**P1 — если успеем:** VLM-описания и структурированный JSON, видео (сцены+ключевые кадры), ASR для аудио/видео, почти-дубли, лица/кластеры персон (opt-in), «умные папки», карта, watch-режим.

**P2 — после v0.1:** диаризация, авто-хайлайты, эстетический скоринг, интеграции с Lightroom/Capture One, NAS-режим, плагины, multi-user, шифрование каталога.

**Не делаем никогда (осознанно):** авто-удаление файлов, облако по умолчанию, определение эмоций/расы/пола/привлекательности, «улучшение» оригиналов, оценка людей.

## 2. Архитектура: 4 процесса, а не один монолит

```
┌───────────────────────────────────────────────────────────────┐
│  UI Shell (Tauri 2 / pywebview)  — окно, меню, трей, обновления │
│      ↕ IPC / HTTP+token (только 127.0.0.1)                      │
├───────────────────────────────────────────────────────────────┤
│  Engine API (FastAPI)                                         │
│   • каталог SQLite (+FTS5 +sqlite-vec)  • правила/планы/undo    │
│   • очередь задач (jobs) • превью-кэш • экспорт метаданных      │
├───────────────────────────────────────────────────────────────┤
│  Worker pool (отдельные процессы, sandbox, rlimits, timeout)    │
│   • parser-worker: exiftool/libvips/rawpy/ffmpeg (НЕ доверенный │
│     вход → изоляция обязательна, см. THREAT_MODEL T05)          │
│   • ai-worker: ONNX Runtime (embeddings/OCR/детекторы)          │
│   • vlm-worker: llama.cpp server (опционально, по профилю)      │
├───────────────────────────────────────────────────────────────┤
│  Model store: ~/.kadr/models (sha256, версии, докачка, оффлайн) │
└───────────────────────────────────────────────────────────────┘
```

**Почему так:**
- Парсеры медиа — главная RCE-поверхность. Падение/компромисс воркера не должен ронять UI и каталог.
- ML-рантаймы конфликтуют по зависимостям и памяти; отдельный процесс = можно убить по OOM и перезапустить.
- Тяжёлый VLM не обязателен: продукт полностью работает на «Lite»-профиле (метаданные + эмбеддинги + OCR).
- Один и тот же Engine обслуживает UI, CLI и (в P2) NAS-режим — без переписывания.

**Сквозные принципы:** контент-адресация (`blake3` файла) как ключ идемпотентности; каждый AI-результат хранит `model_id + model_rev + prompt_rev` (можно переобработать при обновлении модели); любой мутабельный шаг пишет журнал до действия (write-ahead).

## 3. Движок сортировки — ядро продукта (в ТЗ недоописано)

### 3.1 Правила как декларативный DSL (YAML/JSON) + визуальный редактор

```yaml
version: 1
library_root: "/media/Photo"
safety:
  mode: copy              # copy | move | hardlink   (по умолчанию copy)
  verify: blake3          # проверка после копирования
  never_delete: true
  keep_sidecars: true     # .xmp/.aae/.dop/.pp3 переезжают вместе с файлом
  collision: suffix       # suffix | skip | ask | hash

rules:
  - id: docs_and_screens
    stop: true                        # первое совпадение останавливает цепочку
    when:
      all:
        - ai.scene_type: { in: [document, receipt, whiteboard, screenshot] }
        - ai.confidence: { gte: 0.75 }
    then:
      path: "Docs/{date:%Y}/{ai.doc_kind|unknown}"
      tags: ["документ"]

  - id: jobs
    when:
      all:
        - ai.event_type: { in: [wedding, concert, sport] }
        - date: { between: ["2025-05-01", "2025-10-31"] }
    then:
      path: "Jobs/{date:%Y-%m-%d} {ai.event_type}/{camera.model|nobody}"

  - id: people
    when: { persons: { any: true } }
    then:
      path: "People/{person.primary}/{date:%Y}"

  - id: default
    then:
      path: "Archive/{date:%Y/%Y-%m-%d}/{kind}"     # kind = photo|video|audio|raw

fallback:
  path: "_Unsorted/{file.mtime:%Y-%m}"
  review: true                                     # попадает в «инбокс проверки»
```

Операторы: `eq, in, gte/lte, between, contains, regex, exists, any/all/not`. Поля: всё из каталога (`date`, `camera.*`, `gps.*`, `kind`, `ext`, `size`, `ai.*`, `tags`, `persons`, `quality.*`, `dup.*`).
Правила хранятся в БД, версионируются, экспортируются/импортируются файлом → **сообщество сможет делиться наборами правил** (готовые пресеты: «Свадьба», «Семейный архив», «Сток», «Видеопродакшн»).

### 3.2 Токены шаблона пути

`{date:%Y-%m-%d}` `{date.source}` `{camera.make}` `{camera.model}` `{lens}` `{iso}` `{kind}` `{ext}` `{ai.scene_type}` `{ai.event_type}` `{ai.caption_short}` `{person.primary}` `{geo.country}/{geo.city}` `{dup.group}` `{file.stem}` `{hash:8}` `{counter}`.
Все подстановки проходят **санитизацию** (см. THREAT_MODEL T06): allowlist символов, обрезка длины, запрет `..`, абсолютных путей, UNC, ADS, зарезервированных имён Windows.

### 3.3 Иерархия источников даты (и её прозрачность)

`EXIF DateTimeOriginal (+OffsetTimeOriginal)` → `EXIF CreateDate` → `XMP DateCreated` → `QuickTime CreationDate (UTC!)` → `ID3 TDRC` → паттерн в имени файла (`IMG_20240715_132200`, `VID-2024...`, `Screenshot 2024-...`) → `mtime` (последнее средство).
Каждому ассету пишем `taken_at_source` и `date_confidence`; в UI показываем бейдж «дата из имени файла — проверьте». Правило может фильтровать по источнику (`date.source != mtime`) — это то, чего нет у большинства сортировщиков.

### 3.4 Пайплайн исполнения: dry-run → план → выполнение → откат

1. **Scan** (обход ФС, только stat + быстрые метаданные) → индекс.
2. **Analyze** (по профилю: хэши, pHash, эмбеддинги, OCR, VLM) — возобновляемо, идемпотентно.
3. **Plan**: расчёт `src → dst` для всех ассетов, детект коллизий, нехватки места, циклов (dst внутри src), сетевых путей. Пользователь видит **дерево «что куда» + счётчики + примеры**.
4. **Execute**: журнал в SQLite **до** каждого действия; copy → verify hash → (при move) delete source; сохранение mtime/прав; батчами, с паузой/возобновлением, устойчиво к обрыву диска и закрытию приложения.
5. **Undo**: обратный проход по журналу (в обратном порядке), с проверкой, что файл не менялся после операции; частичный undo; «Undo последней раскладки» — кнопка на видном месте.

Cross-device move: `copy+verify+unlink`, а не `rename`. Никогда не удаляем без верификации. Удаление (когда пользователь просит) — только в системную корзину.

### 3.5 Краевые случаи ФС, которые обязаны быть в тестах

| Кейс | Что делаем |
|---|---|
| Windows MAX_PATH 260 | длинные пути (`\\?\`), предупреждение в плане, обрезка токенов |
| Зарезервированные имена (`CON`, `NUL`, `COM1`), запрещённые `<>:"/\|?*`, точка/пробел в конце | санитизация + префикс/суффикс |
| macOS NFD vs Windows/Linux NFC | нормализация имён в NFC, сравнение с учётом ФС |
| Case-insensitive ФС (Win/macOS) | детект коллизий `IMG.jpg` vs `img.JPG` |
| Разные тома / внешние диски | copy+verify, оценка свободного места до старта |
| Symlink / junction / alias | не следуем по умолчанию (защита от выхода за root) |
| Сетевые диски / NAS / SMB | отдельный флаг «медленная ФС», меньше параллелизма, retry |
| Файл занят (Windows lock), антивирус | retry с backoff, понятная ошибка в отчёте |
| **Облачные заглушки** (OneDrive/iCloud «только в облаке») | не гидратируем массово: детект placeholder-атрибута, спрашиваем пользователя |
| Диск отвалился / кончилось место посреди run | безопасная остановка, журнал консистентен, resume |
| Целевая папка внутри источника | детект и запрет рекурсии |
| Повторный запуск | идемпотентность по контент-хэшу: уже разложенное не трогаем |
| Unicode/emoji/пробелы в путях | сквозные тесты на 3 ОС |
| Битые/обрезанные файлы, нулевой размер | карантин-папка + отчёт, не падаем |
| Экзотика: HEIC/AVIF/CR3/ARW/DNG/BRAW/R3D/ProRes | матрица поддержки с явным «не поддержано → _Unsorted» |

### 3.6 Ассет ≠ файл (важно для фотографов)

Группируем в один **ассет**: `RAW + JPEG + .xmp`, Live Photo (`HEIC + MOV`), burst-серии, GoPro/DJI `.LRV/.THM`, прокси-файлы, `.aae` (правки iPhone), `.dop` (DxO), `.pp3` (RawTherapee).
Правила применяются к ассету, перемещается **вся группа целиком**, в UI — один элемент с бейджами. Иначе получим разорванные пары RAW/JPEG — это то, за что продукт проклянут.

### 3.7 Бюджеты производительности (целевые, ⚠️ замерить на M0)

| Операция | Цель на 8-ядерном CPU-ноутбуке |
|---|---|
| Скан + базовые метаданные | ≥ 300 файлов/с (SSD) |
| Хэш + pHash + превью | ≥ 60 фото/с |
| Эмбеддинг (SigLIP-base, int8 ONNX) | 10–25 фото/с |
| OCR | 2–6 фото/с |
| VLM-caption 2B Q4 | CPU 1–4 с/фото, Apple Silicon/GPU 0.3–1 с/фото |
| Видео 10 мин (сцены + 12 ключевых кадров + ASR) | ≤ 60 с |
| 10 000 фото «под ключ», Lite-профиль | ≤ 10 мин |

Всё resumable, с прогрессом, паузой, ограничением потоков и «не мешать работе» (throttle при работе от батареи).

## 4. Оболочка-каталогизатор

### 4.1 Модель данных (набросок DDL)

```sql
volumes(id, uuid, label, root_path, last_seen);
assets(id, content_hash, kind, bytes, width, height, duration_ms,
       taken_at, taken_at_source, date_confidence, tz,
       camera_make, camera_model, lens, gps_lat, gps_lon, phash, quality_json);
files(id, asset_id, volume_id, rel_path, ext, mtime, is_primary, exists_flag);
meta_raw(asset_id, tool, tool_version, json);              -- сырой exiftool JSON, immutable
ai(asset_id, task, model_id, model_rev, prompt_rev, output_json, confidence, created_at);
tags(id, name, parent_id, alias_of);                       -- иерархия + синонимы RU/EN
asset_tags(asset_id, tag_id, source, confidence, verified_by, created_at);
faces(id, asset_id, bbox, embedding, cluster_id, person_id);   -- opt-in
persons(id, display_name, consent_flag);
embeddings(asset_id, model_id, vec);                       -- float16 + sqlite-vec ANN
fts(asset_id, caption, ocr_text, asr_text);                -- FTS5 (ru+en)
collections(id, kind, name, query_json);                   -- static | smart
rules(id, ord, yaml, enabled);
plans(id, job_id, mode, summary_json, state, created_at);
plan_items(id, plan_id, asset_id, src, dst, action, state, error);
journal(id, plan_id, seq, action, src, dst, hash, done_at, undone_at);
review_queue(id, asset_id, reason, severity, payload_json, state);
jobs(id, kind, state, progress, error, started_at, finished_at);
```

Ключевые решения: **источник истины — БД**, файлы — производные; `meta_raw` неизменяем (можно переиграть обработку без повторного чтения диска); теги имеют **provenance** (`model` / `user` / `import`) и `confidence` — пользовательский тег никогда не перезаписывается моделью.

### 4.2 Поиск — три слоя в одном поле ввода

1. **Структурный**: `камера:Sony date:2025-07..2025-08 rating>=4 kind:video`.
2. **Полнотекстовый**: OCR-текст, ASR-реплики, подписи (FTS5, русская морфология).
3. **Семантический**: «закат на пляже с собакой» → эмбеддинг текста → ANN по картинкам/кадрам; поиск по картинке-примеру; «похожие на это».
Плюс фасеты (даты, камеры, теги, места, люди), таймлайн, карта, сохранённые запросы = «умные папки» **без перемещения файлов**.

### 4.3 Экраны

`Library` (галерея, ленивые превью, filmstrip) · `Timeline` · `Map` · `Duplicates` · `People (opt-in)` · **`Review inbox`** · `Rules & Plans` (визуальный редактор + предпросмотр дерева) · `Jobs` · `Settings`.
Горячие клавиши в духе Photo Mechanic (1–5 рейтинг, цветные метки, `X` reject, стрелки, пробел = full screen), батч-правка тегов, экспорт XMP/IPTC, «показать в Explorer/Finder», Undo-кнопка всегда на виду.

### 4.4 Review inbox — место, где сходятся UX и безопасность

Сюда попадает всё «неуверенное»: низкая уверенность модели, расхождение CLIP vs VLM (детектор состязательных атак), подозрение на prompt-injection в метаданных, найденный PII, почти-дубли, дата из mtime.
Это одновременно и UX-фича («ничего не решаем молча»), и **защитный контур** из §4 ТЗ, доведённый до продукта.

### 4.5 Интероп

Экспорт/импорт XMP (Lightroom, Capture One, digiKam, Darktable), чтение рейтингов/меток/ключевых слов из существующих XMP, «не перетирать чужие поля» (merge, а не replace), CSV/JSON-экспорт каталога. В P2 — чтение каталога Lightroom (`.lrcat`) как источника «человеческой» разметки.

## 5. Куда именно писать теги: «свойства файла» — это 4 разных места

| Носитель | Поле | Что увидит пользователь | Инструмент | Риск |
|---|---|---|---|---|
| **XMP sidecar** `file.xmp` | `dc:subject`, `dc:description`, `lr:hierarchicalSubject`, `xmp:Rating`, `xmp:Label` | Lightroom/C1/Bridge/digiKam | свой writer (XML) или exiftool | нет риска для оригинала ✅ |
| JPEG/TIFF/PNG/HEIC (embedded) | XMP + IPTC IIM (`Keywords`, `Caption-Abstract`), EXIF `ImageDescription` | **Windows Explorer: «Теги», «Название», «Комментарии»**; macOS Finder/Spotlight | exiftool | перезапись файла → нужен бэкап/атомарная запись |
| MP4/MOV | XMP в `uuid`-box, `©cmt`, `©des`, ключевые слова QuickTime | Finder/Explorer частично, Premiere/Resolve | exiftool/ffmpeg `-metadata` | переупаковка контейнера, ⚠️ не для BRAW/R3D |
| MP3/FLAC/M4A | ID3v2 `TIT2/TCON/COMM/USLT`, `TPUB` | плееры, Explorer | mutagen |низкий |
| **ФС-атрибуты** | Win: `IPropertyStore` (`System.Keywords`, `System.Comment`); macOS: Finder comment + Spotlight importer; Linux: `user.xdg.tags`/`user.xdg.comment` xattr | «Свойства» и поиск ОС **без всякого EXIF** | платформенные адаптеры | xattr теряются при копировании на FAT/exFAT/некоторые NAS ⚠️ |
| Каталог (БД) | всё, включая эмбеддинги и версии моделей | наше приложение | SQLite | не переносится вместе с файлом → нужен экспорт |

**Политика по умолчанию (предлагаю):**
1. Пишем **sidecar XMP** для всех типов (включая RAW — внутрь RAW **никогда**).
2. Embedded-запись в JPEG/PNG/MP4/MP3 — **opt-in** галочка «вписывать в файл (для Explorer/Lightroom)», с атомарной записью и проверкой.
3. ФС-атрибуты — opt-in «показывать теги в свойствах файла ОС» (это ровно ваш запрос «записывать в свойства», но честно: без embedded XMP Explorer теги не увидит).
4. Всегда сохраняем `AI-generated` provenance: `XMP-dc:creator` не трогаем, свои поля пишем в namespace `kadr:` + стандартные `dc:subject/description`, чтобы чужие программы их читали.
5. Экспортные пресеты приватности: «Сток» (максимум тегов, GPS убрать), «Соцсети» (убрать GPS/серийники/лица), «Архив» (всё).

## 6. Кроссплатформенность для «неподготовленных людей»

### 6.1 Почему Docker не подходит как основной способ доставки

| Проблема | Последствие для фотографа |
|---|---|
| Docker Desktop требует WSL2/Hyper-V, включение виртуализации, иногда прав админа и обновления BIOS-настроек | 30–60 минут боли до первого запуска |
| Лицензия Docker Desktop платная для части компаний | юридический барьер |
| RAM/CPU overhead + образ на 5–10 ГБ с torch/CUDA | «съел весь диск» |
| **Нет GPU на macOS внутри контейнера** (Metal недоступен) | VLM тормозит в разы |
| Проброс томов, права на файлы, UID/GID, съёмные диски | «не видит мою карту памяти» |
| Нет интеграции с ОС (меню, трей, «Открыть с помощью», drag&drop, корзина) | не похоже на приложение |
| Обновления, антивирусы, корпоративные политики | саппорт-ад |

**Вывод:** Docker — для разработчиков/исследователей (ваш §7.4 deliverable остаётся), для CI и для **опционального** self-hosted NAS-режима (продвинутые пользователи, P2). Основной канал — нативный установщик.

### 6.2 Варианты упаковки

| Вариант | Что это | Плюсы | Минусы | Кому |
|---|---|---|---|---|
| **A. Tauri 2 + Python sidecar** ⭐ | Rust-оболочка (системный webview) + наш FastAPI-движок как бинарь | установщик 15–40 МБ + модели отдельно; нативные меню/трей/автообновление; нормальная подпись; UI — обычный веб-стек | нужно собрать Python-sidecar (PyInstaller/Nuitka) и связать lifecycle | **рекомендую для v0.1** |
| B. pywebview + PyInstaller | всё на Python, окно через системный webview | быстрее всего сделать, один язык | размер 300–800 МБ с ML; антивирусные false-positive; автообновление и подпись руками; хрупкие сборки ML-зависимостей | быстрый PoC/бета «для своих» |
| C. Electron + Python sidecar | как A, но Chromium внутри | предсказуемый рендер, зрелая экосистема | +150–250 МБ, RAM | если UI станет очень сложным |
| D. Tauri + Rust + ONNX Runtime (без Python) | всё нативно | самый маленький и быстрый дистрибутив, минимум зависимостей | ML-экосистема на Rust беднее, переписывать пайплайны | долгосрочная цель v1.0 |

⚠️ Решение за вами (вопрос 1). Мой выбор: **A**, при этом Engine с первого дня умеет работать как CLI + локальный сервер, чтобы вариант B/D остался возможен без переделок.

### 6.3 ML-рантайм без «поставьте ещё пять программ»

- **ONNX Runtime** (CPU; DirectML на Windows, CoreML на macOS) — эмбеддинги, OCR, детекторы лиц/объектов, качество. Один вендоренный бинарь, без torch в дистрибутиве.
- **llama.cpp** как встроенный sidecar-server для VLM (GGUF). официальные `Qwen3-VL-2B/4B-Instruct-GGUF` работают на CPU/CUDA/Metal через llama.cpp/Ollama — см. [HF](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct-GGUF).
- **Ollama** — только как опция «у меня уже есть сервер» (для энтузиастов и research-трека).
- Никакого `torch`+`ultralytics` в пользовательской сборке (размер + AGPL, см. §9).

### 6.4 Доставка моделей

Base-пакет без моделей (установщик маленький) → **менеджер моделей** в приложении: список профилей, размеры, скачивание с возобновлением, проверка `sha256`, зеркало, оффлайн-бандл («скачать всё одним файлом» для тех, у кого плохой интернет), явный индикатор «работаем оффлайн, ничего не уходит».
Ориентировочные размеры: embeddings 150–400 МБ (int8), OCR 20–80 МБ, face-detector 5–20 МБ, ASR small 250 МБ / turbo 800 МБ, VLM 2B Q4 ≈ 1.5–2 ГБ. ⚠️ Уточнить на M0.

### 6.5 Подпись, нотаризация, обновления

| ОС | Что нужно | Цена/боль |
|---|---|---|
| Windows | code signing (иначе SmartScreen «неизвестный издатель») | Azure Artifact Signing (бывш. Trusted Signing) ≈ **$9.99/мес**, но для физлиц доступен **только США/Канада**; иначе OV-сертификат $150–300/год ([MS docs](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options)). Репутация SmartScreen набирается скачиваниями — предупреждения возможны и с подписью |
| macOS | Apple Developer **$99/год** + нотаризация, hardened runtime, отдельные arm64/x86_64 (или universal) | без этого «приложение повреждено» |
| Linux | AppImage (универсально) + `.deb`/`.rpm`; Flatpak — позже | подпись не нужна, но нужны тесты на glibc/wayland/X11 |

Автообновление: Tauri updater с подписанными манифестами; каналы `beta`/`stable`; «отложить обновление» (фотограф не хочет обновлений посреди сдачи проекта).

### 6.6 Первый запуск: путь за 5 минут

Установил → открыл → выбрал папку («перетащите папку сюда») → выбрал профиль качества (авто-детект железа) → приложение индексирует в фоне с прогрессом → показывает галерею и предлагает 3 готовых пресета раскладки → **предпросмотр дерева** → «Применить (копировать)» → «Откатить» доступно всегда.
Ни терминала, ни Python, ни Docker, ни `ollama pull`.

### 6.7 Профили качества (⚠️ вопрос 2)

| Профиль | Железо | Что включено | Скорость |
|---|---|---|---|
| **Lite** | любой ноутбук 8 ГБ, CPU | метаданные, хэши/pHash, дубли, эмбеддинги+поиск+zero-shot теги, OCR | быстро,не жрёт батарею |
| **Balanced** | 16 ГБ, Apple Silicon / CPU 8+ ядер | + VLM 2B: подписи, структурированный JSON, событие/сцена; ASR small | средне |
| **Pro** | 16–32 ГБ + GPU 8 ГБ+ | + VLM 4–8B, ASR turbo, лица/кластеры, почти-дубли, видео-хайлайты | качество максимум |

Профиль выбирается автоматически, но виден и переопределяем. Продукт **не деградирует до бесполезности** без GPU — это ключ к «массам».

## 8. Боевой тест v0.1 в сообществе фотографов и видеографов

**Набор:** 20–50 человек, обязательно все 3 ОС, минимум 5 с архивом >100k файлов, минимум 5 видеографов, минимум 3 «непрокачанных» пользователя (проверка UX).

**Условия входа (в бета-соглашении):**
- работаем **на копии** архива или в режиме `copy` (по умолчанию);
- у участника есть бэкап (мы явно спрашиваем);
- продукт ничего не удаляет; откат доступен;
- телеметрия и краш-репорты — **opt-in**, без содержимого файлов и без PII;
- известные ограничения перечислены честно (список форматов, точность тегов, «лица — экспериментально»).

**Метрики продукта:** время до первого результата; скорость индексации 10k файлов; доля файлов, разложенных «правильно» по мнению владельца (цель ≥ 90% на пресете «по дате», ≥ 75% на «по контексту»); precision@5 автотегов; доля ручной правки; crash-free sessions ≥ 99%; количество обращений в саппорт на пользователя; SUS-опрос ≥ 70.

**Артефакты:** `BETA_GUIDE.md` (10 минут), `KNOWN_LIMITATIONS.md`, шаблон баг-репорта (авто-сбор версий/ОС/профиля без медиа), канал (Telegram/Discord + GitHub Issues), еженедельный дайджест «что починили», публичный roadmap.

**Golden-датасет:** 500–1000 файлов с ручной разметкой (сцены, события, качество, дубли, «злые» файлы) — используется и для регрессии качества моделей, и для security-тестов. Собрать из своих архивов + разрешённых стоков; не распространять чужие фото без прав.

## 9. Лицензионная гигиена (блокирующий вопрос для «в массы»)

| Компонент из ТЗ | Лицензия / риск | Замена / решение |
|---|---|---|
| `ultralytics` (YOLOv8/11) + их веса | **AGPL-3.0**, включая обученные модели; коммерческое встраивание требует платной Enterprise-лицензии ([ultralytics.com/license](https://www.ultralytics.com/license)) | Apache/MIT-детекторы: RT-DETR (Apache-2.0), YOLOX (Apache-2.0), D-FINE, или вообще обойтись CLIP-zero-shot + VLM |

| `jina-clip-v2` (мультиязычные эмбеддинги) | **CC-BY-NC-4.0** — нельзя в коммерческий продукт ([jina.ai](https://jina.ai/models/jina-clip-v2/)) | SigLIP 2 (Apache-2.0), OpenCLIP (MIT), мультиязычный текстовый энкодер отдельно (Apache/MIT) |
| Qwen2.5-VL / **Qwen3-VL 2B/4B** | Apache-2.0 (проверить конкретный чекпойнт) | ок для продукта; GGUF официально есть |
| SmolVLM2 / MiniCPM-V | Apache-2.0 / собственная «free commercial» с условиями — читать | SmolVLM как лёгкая альтернатива |
| Whisper / faster-whisper | MIT | ок |
| `pyannote` (диаризация) | gated-модели на HF, условия использования | P2, отдельное согласие пользователя |
| `pytesseract` / Tesseract | Apache-2.0 | ок, но нужен бинарь в комплекте |
| EasyOCR / PaddleOCR / RapidOCR | Apache-2.0 (⚠️ проверить веса) | RapidOCR (ONNX) — лучший вариант для дистрибутива |
| **exiftool** | GPL/Artistic (Perl) | распространять как отдельный бинарь с указанием лицензии и исходников; либо свой XMP-writer + `libexiv2`/`pyexiv2` (GPL — осторожно) |
| **ffmpeg** | сборка LGPL vs GPL зависит от флагов | брать **LGPL-сборку**, динамическая линковка, не включать GPL-компоненты (x264 и т.п.) |
| `torch` в дистрибутиве | BSD, но +2 ГБ и CUDA-блобы | не тащить в пользовательскую сборку (ONNX/GGUF) |
| `llm-guard`, `presidio` | MIT | ок по лицензии, но тяжёлые по моделям → опциональный профиль |
| Модели с HF вообще | `trust_remote_code=True` = исполнение чужого кода | **никогда**; только `safetensors`/GGUF, пиннинг ревизии + sha256 |

Действие: файл `LICENSES.md` + SBOM (CycloneDX) в CI + job, который падает при появлении AGPL/NC-зависимости в пользовательском профиле.
