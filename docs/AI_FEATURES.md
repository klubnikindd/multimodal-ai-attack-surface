# Меню AI-фич: «какие ещё возможны варианты?»

> Ответ на вопрос из запроса. Каждая фича оценена по: ценности для фотографа/видеографа, стоимости (размер модели, скорость), лицензии и приоритету (P0 — v0.1, P1 — бета+, P2 — позже).
> Скорости — **оценки** для 8-ядерного CPU-ноутбука / Apple Silicon, требуют замера на M0. Все фичи работают оффлайн.

## 0. Пять уровней «интеллекта» — важно не прыгать сразу на L4

| Уровень | Что это | Стоимость | Даёт |
|---|---|---|---|
| **L0. Детерминированные метаданные** | EXIF/XMP/QuickTime/ID3: дата, камера, объектив, GPS, ориентация, длительность, кодек | ~0 | 80% пользы «сортировщика по дате/камере/месту». Работает всегда |
| **L1. Дешёвые сигналы и классика CV** | pHash/dHash, резкость/экспозиция/шум, детект скриншотов и документов, палитра, гистограммы, scene-cut | мс/файл | дубли, брак, «фото vs скриншот», обложки |
| **L2. Эмбеддинги (CLIP/SigLIP)** | вектор изображения ↔ вектор текста | 10–25 фото/с | **семантический поиск фразой**, zero-shot теги, похожие кадры, почти-дубли, кластеры событий |
| **L3. Специализированные модели** | OCR, ASR, детекторы лиц/объектов, аудио-теггинг, эстетика | 0.2–3 с/файл | текст с фото, речь с видео, люди, «что за звук» |
| **L4. VLM (vision-language)** | подписи, структурированное описание сцены, рассуждения, ответы на вопросы о кадре | 0.3–4 с/кадр | «человеческое» описание, событие, контекст, keywords для стоков |
| ~~L5. Агент с инструментами~~ | LLM сама вызывает функции/ходит в сеть | — | **не делаем в v0.1**: это главный вектор prompt-injection → RCE/эксфильтрация |

Ключевая мысль: **L0+L1+L2 дают продукт, который уже лучше PhotoMove Pro**, и работают на любом ноутбуке. L4 — «вау», но опционален и включается профилем.

## 1. Фото: каталог фич

### 1.1 Технические сигналы (L1) — дёшево, точно, loved by photographers

| Фича | Метод/модель | Приоритет | Куда пишется |
|---|---|---|---|
| Точные дубликаты | blake3 контента | P0 | БД, отчёт |
| Почти-дубли (кроп, ресайз, фильтры, JPEG-пережатие) | pHash + эмбеддинги + геометрическая проверка | P1 | review inbox (не удаляем!) |
| Группировка burst/серий и выбор «лучшего кадра» | временные кластеры + резкость + открытые глаза + эстетика | P1 | `kadr:bestOfGroup`, коллекция |
| Детект брака: расфокус, шевелёнка, пересвет/недосвет, шум | Laplacian variance, гистограммы, лёгкая CNN | P1 | `kadr:quality.*`, фильтр «скрыть брак» |
| Скриншот / мем / графика vs фотография | правила (нет EXIF, размеры экрана, палитра) + мини-классификатор | P0 | `ai.media_class` — правило «скриншоты отдельно» |
| Документ / чек / визитка / доска с записями | классификатор + OCR-эвристики | P0 | `ai.scene_type=document` |
| Авто-ориентация и «правильный» поворот | EXIF + детектор ориентации | P0 | превью, без изменения оригинала |
| Палитра и доминирующие цвета | k-means в Lab | P2 | `kadr:palette`, поиск «по цвету» |
| Панорамы / вертикальные / квадратные, кроп-фактор | геометрия + EXIF | P1 | фильтры |
| Скан/фото документа → выравнивание перспективы | классика CV | P2 | отдельная копия (не оригинал) |

### 1.2 Семантика на эмбеддингах (L2) — главный «нейро»-козырь

| Фича | Как | Приоритет |
|---|---|---|
| **Поиск фразой**: «ночная улица с neon-вывесками», «собака бежит по пляжу» | SigLIP 2 / OpenCLIP text→image ANN (sqlite-vec) | P0 |
| **Zero-shot теги** по настраиваемому словарю (сцена, локация, тип события, погода, время суток, наличие людей) | сравнение с наборами промптов, порог уверенности | P0 |
| Поиск по примеру («ещё такие же») и «похожие в библиотеке» | image→image ANN | P0 |
| Авто-альбомы / кластеры событий | эмбеддинги + время + GPS (HDBSCAN) | P1 |
| «Найди кадр, который я помню смутно» | текст + фильтры + rerank | P1 |
| Поиск по эскизу/композиции | sketch-энкодер | P2 |
| Кросс-язычность: запрос по-русски → теги по-английски | мультиязычный текстовый энкодер с разрешённой лицензией (⚠️ не jina-clip-v2: CC-BY-NC) | P1 |

**Почему это лучше «просто VLM»:** в 100–1000 раз дешевле, детерминированно, легко порог уверенности, нет генеративных галлюцинаций, нет prompt-injection через пиксели в генерации текста.

### 1.3 VLM-фичи (L4) — то, что вы описали в ТЗ, и не только

| Фича | Выход | Приоритет |
|---|---|---|
| Подпись сцены (1–2 предложения, RU+EN) | `dc:description` | P1 |
| **Структурированный JSON** (главное!) | `scene_type, setting, subjects[], actions[], event_type, time_of_day, weather, lighting, indoor_outdoor, mood, text_present, quality_issues[]` | P1 |
| Keywords для стоков (30–50 тегов, EN, без спама) | `dc:subject` + `lr:hierarchicalSubject` | P1 |
| Alt-text для доступности и SEO | `kadr:altText` | P1 |
| Название/заголовок кадра для каталога | `dc:title` | P2 |
| «О чём эта съёмка» — саммари альбома/папки | текст по агрегату кадров | P2 |
| Ответы на вопросы о фото в UI («есть ли тут логотип?») | локальный VLM, только чтение | P2 |
| Детект «фото товара/еды/интерьера/авто» для нишевых пресетов | zero-shot + VLM | P2 |
| Определение языка текста на фото | OCR + langid | P1 |
| Подсказки по кадрированию/композиции | правила + saliency | P2 |

**Формат вывода VLM — только строгая схема** (JSON Schema / grammar-constrained decoding), с валидацией и отбрасыванием всего лишнего. Это одновременно качество и защита от инъекций (см. THREAT_MODEL T01/T02).

```json
{
  "scene_type": "wedding_ceremony",
  "setting": "outdoor_garden",
  "subjects": ["bride", "groom", "guests"],
  "actions": ["exchange_rings"],
  "event_type": "wedding",
  "time_of_day": "golden_hour",
  "weather": "clear",
  "lighting": "natural_backlight",
  "mood": "joyful",
  "text_present": false,
  "quality_issues": [],
  "keywords_en": ["wedding", "ceremony", "rings", "garden", "golden hour"],
  "confidence": 0.82
}
```

### 1.4 Люди (особый режим, opt-in)

| Фича | Комментарий | Приоритет |
|---|---|---|
| Детект лиц + количество людей | полезно для правил «есть люди / нет людей», «портрет vs пейзаж» | P1 |
| Кластеризация персон **без имён** («Человек 1», «Человек 2») | пользователь сам присваивает имя локально | P1 |
| «Разложить по папкам с именами людей» (из вашего ТЗ) | работает только после того, как пользователь назвал кластер | P1 |
| Открытые/закрытые глаза, улыбка (для отбора burst) | технический признак качества дубля, не «эмоция человека» | P2 |
| ~~Определение возраста/пола/расы/эмоций/привлекательности~~ | **не делаем**: юридические риски (EU AI Act, GDPR ст.9, BIPA), этика, ложные срабатывания | ✗ |

Юридически: биометрическая идентификация — особая категория данных. Требуется явное согласие, локальная обработка, кнопка «удалить все данные о лицах», отдельный документ `PRIVACY.md`. По умолчанию — **выключено**.

### 1.5 OCR и текст (L3)

| Фича | Приоритет |
|---|---|
| Текст с фото → полнотекстовый поиск (вывески, документы, номера, слайды, доски с записями) | P0 |
| Авто-имя файла по содержимому («2025-07-12 Чек Лента 1450₽») | P1 |
| Детект «чувствительного» (паспорт, карта, номер авто, адрес) → review inbox + авто-маскирование при экспорте | P0 (это и security-фича) |
| Извлечение таблиц/структуры из документов | P2 |
| Рукописный текст | P2 (качество нестабильно) |

Стек: RapidOCR/PaddleOCR (ONNX, Apache-2.0), Tesseract как fallback. **Текст из OCR — недоверенный ввод** (в пикселях можно написать инъекцию для LLM).

## 2. Видео: пайплайн, а не «распознать видео целиком»

```
видео → метаданные (кодек, длительность, fps, разрешение, bitrate, камера)
      → scene-cut detection (PySceneDetect / TransNetV2)
      → выбор K ключевых кадров на сцену (резкость + разнообразие по эмбеддингам)
      → кадры через фото-пайплайн (L1/L2/L3/L4)
      → аудио-дорожка → ASR (речь) + аудио-теггинг (звук)
      → агрегация по клипу (взвешенно по длительности сцен) + confidence
      → обложка (лучший кадр), авто-чаптеры, тайм-кодированные теги
```

| Фича | Ценность | Приоритет |
|---|---|---|
| Тип контента: интервью / B-roll / дрон / таймлапс / скринкаст / съёмка с рук | правила раскладки для видеографа | P1 |
| Поиск по произнесённой фразе **с тайм-кодом** | killer-фича для монтажа | P1 |
| Транскрипт + субтитры (SRT/VTT) как sidecar | монтаж, доступность | P1 |
| Авто-чаптеры по сценам/темам | навигация по длинному клипу | P2 |
| Технический брак: шевелёнка, расфокус, клиппинг звука, тишина, дропы кадров | отбор дублей | P1 |
| Лучший кадр → обложка (poster) | каталог выглядит нормально | P1 |
| «Найди все дубли, где говорит X» (диаризация) | P2, gated-модели | P2 |
| Авто-хайлайты (пики аудио-энергии + смех/аплодисменты + эстетика) | свадебный/ивент-монтаж | P2 |
| Детект хлопушки/склейки/чёрных кадров | тех-разбор материала | P2 |
| Стабилизированные/нестабилизированные, наличие логотипа/водяного знака | нишевое | P2 |

Запись: XMP в MP4/MOV (`dc:subject`, `dc:description`), sidecar `.xmp` + `.srt`/`.vtt` + `.json` с тайм-кодами; **никогда не перекодируем** оригинал.

## 3. Аудио: отдельный полноценный трек (в ТЗ почти не описан)

| Фича | Метод | Приоритет |
|---|---|---|
| ASR: речь → текст с тайм-кодами, RU/EN + авто-язык | faster-whisper (MIT), small/turbo | P1 |
| Классификация: речь / музыка / шум / тишина / микс | CLAP или PANNs (⚠️ проверить лицензии весов) | P1 |
| Аудио-события: аплодисменты, смех, ветер, дождь, транспорт, стрельба | аудио-теггинг | P2 |
| Музыка: BPM, тональность, энергетика, жанр-приближение | librosa + лёгкая модель | P2 |
| Качество: клиппинг, фон/шум, реверберация, моно/стерео, LUFS | DSP | P1 |
| Идентификация трека (fingerprint) | Chromaprint/AcoustID + MusicBrainz (⚠️ сетевой запрос → opt-in) | P2 |
| Диаризация «кто говорил» | pyannote (gated) | P2 |
| ID3-теги: название, исполнитель, год, обложка | mutagen + существующие теги | P0 |
| Авто-раскладка: «Подкасты / Черновики / Музыка / Закадровый текст / SFX» | правила по ASR+теггинг | P1 |

## 4. Мета-фичи поверх всего (то, что делает продукт «умным», а не «набор моделей»)

1. **Обучение на правках пользователя.** Пользователь исправил тег → это метка. Локальный лёгкий классификатор (linear probe поверх эмбеддингов) дообучается на его библиотеке → персональные теги без облака. P1, очень сильный дифференциатор.
2. **Активное обучение / приоритезация ревью.** Показываем сначала то, где модель не уверена и где правка даст максимум пользы.
3. **Каскад моделей по стоимости.** L0→L1→L2 решает 80% случаев; VLM вызывается только если уверенность низкая или правило требует деталей. Экономия часов процессора.
4. **Ансамбль и перекрёстная проверка** (CLIP vs VLM) — не только качество, но и детектор состязательных атак.
5. **Кэш и версионирование.** Результат привязан к `content_hash + model_rev + prompt_rev`; обновление модели → фоновая переобработка только затронутых задач, с diff-отчётом «что изменилось».
6. **Объяснимость.** У каждого тега — «почему»: уверенность, модель, версия, «подтверждено вами». Фотограф доверяет только объяснимому.
7. **Пресеты словарей по нишам** (свадьба, репортаж, сток, недвижимость, авто, еда, спорт) — словари zero-shot тегов + правила; сообщество делится пресетами.
8. **Приватность как фича.** «Всё локально, ни один байт не уходит» + отчёт «что мы знаем о вашей библиотеке» + кнопка «забыть всё».

## 5. Что осознанно НЕ делаем

- Авто-удаление «плохих» файлов и авто-перезапись оригиналов.
- Облачные API по умолчанию (только явный opt-in, с индикацией и egress-allowlist).
- LLM-агент с инструментами (shell, HTTP, файловые операции) внутри пайплайна обработки недоверенных медиа.
- Определение эмоций/расы/пола/возраста/привлекательности людей, «оценка внешности».
- Скрытая телеметрия с содержимым файлов.
- Генеративное «улучшение»/дорисовка изображений (другой продукт, другие риски).
