# Правила для будущих версий (v3, v4…)

* Имя: vN.md, где N — целое, монотонно растёт. Без `-final`, `-draft`, `-new`, `-latest`.

* Статусы: draft → current → archived. Ровно один current в любой момент.

* Переход: новый файл создаётся копией current; в старом меняется баннер на archived + superseded_by; в новом — supersedes; таблица в README.md обновляется в том же PR.

* Git-теги: аннотированные spec/v1.0, spec/v2.0 на коммите, где версия стала current. Это даёт стабильную ссылку вида https://github.com/org/repo/blob/spec/v2.0/docs/spec/v2.md, которая не сломается, даже если файл переименуют.

* Разделитель версий спеки и продукта: версия спеки — это ревизия документа; версия продукта — релиз (v0.1.0-beta). Они не совпадают и не должны. M0–M6 — это майлстоуны внутри спеки v2, а не «версии спеки».
