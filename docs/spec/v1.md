## 1. Общие сведения

*   **Название проекта:** Multimodal AI Attack Surface (MIAS)
*   **Тип проекта:** Кроссплатформенное десктопное приложение / Security Research PoC.
*   **Цель:** Создать инструмент для автоматической каталогизации и сортировки медиафайлов с помощью нейросетей (VLM/CLIP), в ходе разработки выявить и продемонстрировать векторы атак на vision-модели, а также реализовать защитный контур (Defense-in-Depth) для мультимодальных пайплайнов.

## 2. Целевая аудитория

*   **Основная (Продукт):** Фотографы, видеографы, контент-мейкеры с большими архивами неструктурированных медиафайлов, фото/видео энтузиасты (любители).
*   **Вторичная (Исследование):** Специалисты по AI Security, демонстрирующие навыки Threat Modeling и защиты ML-систем (для портфолио).

---

## 3. Функциональные требования (Продукт)

### 3.1. Индексация и сортировка
*   **Чтение медиа:** Поддержка фото (JPEG, PNG, RAW), видео (MP4, MOV) и аудио (MP3, WAV).
*   **Правила сортировки:** Возможность задавать правила (например, «Сортировать по дате съемки», «Сортировать по распознанному контексту», «Разложить по папкам с именами людей»).
*   **Дедупликация:** Поиск дубликатов на основе хэшей или визуального сходства.

### 3.2. Нейросетевые фичи (AI-модуль)
*   **Контекст и объекты:** Использование Vision-Language Model (VLM) для генерации текстового описания сцены (например, `llava`, `qwen2-vl` или локальный CLIP).
*   **OCR (Распознавание текста):** Извлечение текста с фотографий (вывески, документы, номера машин).
*   **Разметка метаданных:** Автоматическая запись сгенерированных описаний и тегов в свойства файла (XMP/IPTC/EXIF) для кроссплатформенной совместимости (чтобы теги не «сгорали» при переносе в другие программы).

### 3.3. Оболочка-каталогизатор
*   **Веб-интерфейс (Local UI):** Легковесный интерфейс на базе `pywebview` или локального сервера FastAPI.
*   **Галерея:** Просмотр медиафайлов, фильтрация по тегам, ручная корректировка автоматической разметки.
*   **База данных:** Локальная SQLite для хранения метаданных, путей и связей (без тяжелых векторных БД для MVP).

## 4. Требования к безопасности (Security Research)

*Это ядро проекта. В ходе разработки необходимо провести аудит и реализовать защиту по следующим векторам:*

### 4.1. Атака: Prompt Injection через метаданные (EXIF/XMP)
*   **Суть:** Злоумышленник передает фото, в теге которого скрыта вредоносная инструкция. При обработке файла пайплайном (например, при генерации общего описания альбома) LLM выполняет команду.
*   **Защита:** Санитизация всех входящих текстовых метаданных. Интеграция `LLM Guard` (сканер `PromptInjection`) перед передачей текста из EXIF в любую LLM.

### 4.2. Атака: Adversarial Images (Состязательные атаки)
*   **Суть:** Специально сгенерированный шум или физический патч на изображении заставляет VLM классифицировать его неверно (например, документ с патчем распознается как «пейзаж»).
*   **Защита:** Использование порогов уверенности (Confidence Thresholds). Если модель не уверена — отправка на ручную проверку. Ансамбль моделей (CLIP + VLM) для перекрестной проверки.

### 4.3. Атака: Утечка PII через метаданные
*   **Суть:** EXIF содержит GPS-координаты дома, серийные номера камеры. Автоматическая запись нейросетевых тегов может дополнительно раскрыть личности (имена на фото).
*   **Защита:** Модуль «Очистка метаданных» перед экспортом. Интеграция Microsoft Presidio для поиска и маскирования PII (имена, лица, координаты) в генерируемых описаниях.

### 4.4. Атака: Supply Chain (Цепочка поставок)
*   **Суть:** Зависимости для работы с vision-моделями (`ultralytics`, `torch`, `opencv`) часто содержат уязвимости (CVE).
*   **Защита:** Настройка CI/CD пайплайна (GitHub Actions). Интеграция `pip-audit` и `Trivy` для сканирования зависимостей и Docker-образов.

## 5. Архитектура и Технологический стек

*   **Язык:** Python 3.12.
*   **ML-стек:** Ollama (для VLM, например, `llava` или `qwen2-vl`), HuggingFace Transformers (CLIP), `pytesseract` или `easyocr` для OCR.
*   **Бэкенд:** FastAPI, Uvicorn.
*   **Фронтенд (UI):** HTML/JS + `pywebview` (для десктопного окна) или Swagger UI (для MVP).
*   **Работа с метаданными:** `exiftool`, `Pillow`.
*   **Безопасность:** `llm-guard`, `presidio-analyzer`, `pip-audit`.
*   **База данных:** SQLite.
*   **Кроссплатформенность:** Docker (для разработки) + `PyInstaller` (для сборки бинарников под Win/Mac/Linux).

## 6. Этапы разработки (Roadmap на 4–5 выходных)

*   **Этап 1: MVP (CLI) — 1 выходной**
    *   Развернуть структуру репозитория.
    *   Написать CLI-скрипт, который читает папку, отправляет фото в локальную VLM (через Ollama) и сохраняет текстовое описание в SQLite.
*   **Этап 2: Векторы атак (Red Teaming) — 1 выходной**
    *   Создать PoC «отравленного» EXIF-файла (Prompt Injection).
    *   Создать скрипт для генерации Adversarial-патча.
    *   Зафиксировать результаты в `SECURITY_NOTES.md`.
*   **Этап 3: Защитный контур (Blue Team) — 1 выходной**
    *   Прикрутить `LLM Guard` на этап чтения метаданных.
    *   Прикрутить `Presidio` на этап генерации описаний.
    *   Настроить CI/CD (`pip-audit`).
*   **Этап 4: UX и Кроссплатформенность — 1–2 выходных**
    *   Добавить простой веб-интерфейс (FastAPI + Jinja2/`pywebview`).
    *   Настроить сборку через `PyInstaller` в один `.exe` (и инструкции для Mac/Linux).
    *   Написать `README.md` с акцентом на безопасность.
