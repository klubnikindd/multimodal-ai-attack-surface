# ADR-0003: Политика работы с файлами и метаданными — «оригиналы неприкосновенны»

- **Статус:** принято (2026-11-12)
- **Контекст:** главный барьер adoption у фотографа — страх потерять или испортить архив. Исходное ТЗ предполагало запись AI-тегов внутрь файлов (EXIF/XMP/IPTC) и не описывало гарантий сохранности при перемещении.
- **Решение:** по умолчанию **копирование с верификацией** и **запись тегов в XMP-sidecar**. Внутрь RAW не пишем **никогда**. Изменение оригиналов, `move` и запись в «свойства ОС» — только явный opt-in. Удаление — только в системную корзину по явному действию пользователя.

## Нормативные правила

1. **Режимы:** `copy` (default) → `move` (opt-in) → `hardlink` (opt-in, только внутри одного тома). Cross-device move = copy + verify + unlink.
2. **Верификация:** blake3 источника и цели; удаление источника при `move` — только после успешной верификации.
3. **Write-ahead журнал:** запись в SQLite **до** каждого действия; атомарность на уровне файла; устойчивость к kill -9, ENOSPC, отвалу тома; полный и частичный **undo**.
4. **Метаданные:** XMP-sidecar для всех типов; embedded-запись (JPEG/PNG/TIFF/HEIC/MP4/MOV/MP3) — opt-in, атомарная (tmp + rename + fsync) с бэкапом заменяемого файла; внутрь RAW (CR2/CR3/NEF/ARW/DNG/RAF/ORF/RW2) — запрещено; BRAW/R3D не переупаковываем.
5. **Merge, не replace:** существующие пользовательские поля, рейтинги, метки, копирайт не перетираются; конфликт → review inbox. Пользовательский тег никогда не перезаписывается моделью.
6. **Группы ассетов:** RAW+JPEG+XMP, Live Photo (HEIC+MOV), burst, `.aae/.dop/.pp3`, `.LRV/.THM`, прокси перемещаются целиком.
7. **Пути:** только allowlist-токены, санитизация сегментов, `realpath(dst)` внутри `library_root`, запрет symlink/UNC/ADS, повторная валидация перед операцией (см. SEC-06).
8. **Приватность экспорта:** пресет `stock` по умолчанию — GPS, серийники, лица выключены; `social`, `archive` — по выбору.
9. **Обещание в UI:** «Оригиналы не изменяются и не удаляются. Любую раскладку можно откатить» — и это должно быть правдой на уровне тестов, а не маркетинга.

## Последствия

**Положительные:** максимальное доверие; продукт можно безопасно давать в бету на реальные архивы; совместимость с Lightroom/Capture One/digiKam через sidecar; отсутствие риска порчи RAW.

**Отрицательные:** `copy` требует свободного места (нужна проверка и понятное сообщение, предложение `move`); sidecar-файлы «мусорят» в папках и теряются при неаккуратном копировании пользователем (нужна подсказка и опция embedded); Windows Explorer не показывает теги без embedded XMP или записи в `IPropertyStore` — это надо честно объяснить в UI.

## Проверка решения

- Property-based тесты генератора путей и правил.
- Fault-injection: kill -9 в середине плана, ENOSPC, отключение тома, заблокированный файл → инвариант «ни один оригинал не потерян и не повреждён», undo восстанавливает побайтово.
- Тест «RAW не изменён»: хэш RAW до и после полного цикла разметки совпадает.
- Тест экспорта `stock`: exiftool-дамп не содержит GPS/серийников/лиц.
