# ADR-0006: корзина приложения как interim для FR-2.8

- **Статус:** принято (2026-11-20)
- **Контекст:** FR-2.8 (v3.1) требует «удаление — только в системную корзину».
  Реализация v0.1 перемещает файлы в корзину приложения `~/.kadr/trash`
  (`config.trash_dir`, `executor._move_to_trash`). Системная корзина
  (Recycle Bin / `NSFileManager.trashItem` / XDG Trash) — платформо-зависимая
  и не реализована в v0.1.

## Решение

1. **v0.1 — interim-корзина приложения.** Удаление выполняется только явным
   действием пользователя и только перемещением в `trash_dir`; `never_delete`
   по умолчанию включён и не отключаем. Исходные файлы никогда не удаляются
   безусловно (undo возвращает из `trash`).
2. **FR-2.8 остаётся невыполненным до системной корзины.** В `STATUS.md`/
   `KNOWN_LIMITATIONS.md` это фиксируется честно; в v3.1 §5.2 стоит пометка,
   что корзина приложения — временное решение.
3. **v0.2 — системная корзина:** Windows Recycle Bin (`IFileOperation` или
   `SHFileOperation`), macOS `NSFileManager.trashItem`, Linux XDG Trash
   (freedesktop spec). При недоступности системной корзины — падение на
   interim-корзину с видимым предупреждением, не тихий деградированный путь.

## Последствия

- Продукт не нарушает SEC-13: журнал, undo и верификация работают поверх
  `trash`; «никогда не delete безусловно» соблюдается.
- Пользователь, ожидающий «файл в корзине ОС», в v0.1 увидит «Kadr-корзину» —
  это задокументировано, а не скрыто.
- Задача системной корзины — `P2-03` плана (v0.2), тикет фиксируется в
  трекере.
